PART 01

核心概念：先搞清楚 Agent 到底是什么

一句话结论：Agent 不是「更会聊天的 LLM」，而是以模型为大脑、围绕目标持续 感知环境 → 规划 → 调用工具 → 记忆 → 反思 的闭环系统。类比：Chatbot 是会说话的策划顾问；Agent 是拿到胜利条件、技能栏、地图和存档后，能连续推进任务的「游戏角色 + 制作人」。

1.1 权威定义与边界

OpenAI（2025）

Agent 是「代表用户独立完成任务」的系统；生产形态包含模型、工具、指令、编排与护栏。——《A Practical Guide to Building Agents》

Anthropic（2024）

Workflow 是「按预定义代码路径编排 LLM 和工具」；Agent 则「动态指挥自己的流程与工具使用」。——《Building Effective Agents》

Google（2024）

Agent 是扩展基础模型能力的程序，通过推理、外部信息与工具，以自导向方式规划并执行目标。——《Agents》白皮书

Lilian Weng（2023）

LLM 是大脑，核心组件为规划（Planning）、记忆（Memory）、工具使用（Tool Use）。——《LLM Powered Autonomous Agents》

概念本质区别通俗类比
LLM Chatbot以「输入—回答」为中心，通常不持续行动资深顾问：能出方案，但等你拍板和执行
Workflow分支和调用顺序由人预先写死固定玩法脚本 / SOP：稳定，但遇到新关卡就停
RPA用规则模拟点击和录入，适合结构化重复任务（IBM 概括为「做」，AI/ML 更接近「思考、学习」）宏脚本玩家：连招快，但 UI 一改版就失灵
AI Agent根据目标自主选择下一步，接收反馈并修正，可跨工具完成长任务会看地图、接支线、换装备、复盘失误的玩家

1.2 核心能力循环

Agent 的运行不是一次流水线，而是一个 直到目标达成、失败阈值触发或人接管 的循环：

感知 Perception读取文本、网页、屏幕、API、文件与事件
≈ 小地图与战斗日志
规划 Planning拆目标、排序、预估依赖，边做边重排
≈ 把主线拆成任务树
行动 Action搜索、写文件、查库、执行代码、操作浏览器
≈ 角色技能栏
记忆 Memory短期=本局临时状态；长期=存档与攻略库
反思 Reflection比对计划、结果与约束，生成下一轮策略
≈ 版本复盘

行动之后从环境获得观察（Observation），写入记忆，再进入下一轮规划 —— 循环往复。

1.3 关键架构范式

ReAct（ICLR 2023）

交替生成 Reasoning → Action → Observation，适合路径不确定的任务。敏捷试玩：每回合先看局势再放技能

Plan-and-Execute

Planner 先生成完整计划，Executor 执行，必要时 Replanner 修正；适合步骤清晰的长任务。先写 GDD 和里程碑，再交给关卡团队执行

Reflection / Reflexion（NeurIPS 2023）

Actor 执行、Evaluator 评价、Self-Reflection 写入情景记忆，用「语言反馈」改进后续尝试。每次失败后写复盘卡，下周目继承经验

Multi-Agent

调度者把任务分给研究、代码、审核等专家 Agent 并处理交接（AutoGen 2023；Anthropic 多 Agent 研究系统 2025）。制作人 + 策划 + 程序 + QA 的迷你工作室

Agentic RAG

检索前先拆解问题，检索中评估证据、补查、交叉验证再综合；区别于「一次向量检索 + 生成」。研究员不是搜一次就写稿，而是多轮查资料、核对来源

1.4 自主性等级：L1–L5

DeepMind《Levels of AGI》（2023）把能力与自主性分开，用类似自动驾驶的分级描述人机关系。注意：这是自主决策权分级，不等于模型能力分级——能力强也不应自动放权。

L1 Tool人完全控制，AI 只是被动工具
L2 Consultant人召唤时给建议
L3 Collaborator人机共管目标
L4 ExpertAI 主导、人监督
L5 Agent高自主，但知道何时求助

1.5 为什么 Agent 被视为通往 AGI 的关键路径 · 里程碑

OpenAI 把 AGI 定义为「在多数有经济价值的工作中超越人类的高度自主系统」。Agent 把「会想」接到「会做」：LLM 是发动机，Agent 是把发动机、方向盘、导航、油箱和刹车装成能上路的车。但 Agent ≠ AGI——通用性、持续学习、世界模型与安全对齐仍是未解问题。

1.6 能力边界与失效模式（PM 必懂）

幻觉

把错误事实当前提，后续计划和动作全部偏航。策划引用错误玩家数据后做平衡性调整

循环

重复同一无效动作、缺少停止条件。NPC 卡在门口不断撞墙

工具误用 / 越权

选错 API、填错参数，或被网页提示注入劫持。把「删除数据库」按钮放进新手村技能栏

上下文爆炸

网页、日志和工具输出塞满窗口，注意力衰减、成本升高（Anthropic 称 context pollution/rot）。

长程误差累积

单步 95% 正确，30 步后整体成功率显著下降。OSWorld 2024 年最佳 Agent 仅 12.24%（人类 72.36%）——「能演示」不等于「可托付」。

产品护栏清单：先用 Workflow 解决确定路径，Agent 只处理开放、分支多、路径不可预知的任务。给它明确胜利条件、最小权限工具白名单、最大步数、失败阈值、结构化输出、可追溯轨迹与回放评测；付款、删除、外发等不可逆动作必须 Human-in-the-loop。

1.7 核心术语速查表

Agent 智能体 · 为达成目标而自主感知、决策并行动的系统
Goal 目标 · 系统要优化的最终结果，相当于胜利条件
Environment 环境 · Agent 可观察并施加影响的网页、文件、软件或物理世界
Observation 观察 · 行动后从环境拿到的新反馈
Action Space 动作空间 · Agent 被允许执行的全部动作集合
Reasoning 推理 · 基于证据和规则形成判断
Reflection 反思 · 对结果和过程做评价，并改进后续策略
Tool Use 工具使用 · 调搜索、代码、数据库、浏览器等外部能力
Function Calling 函数调用 · 模型按预定义 schema 生成函数名与参数，由程序真正执行
Context Window 上下文窗口 · 模型一次能处理的最大 token 范围
Memory 记忆 · 跨步骤保存的信息，分短期（会话内工作记忆）与长期（可跨会话召回）
RAG 检索增强生成 · 先检索外部资料，再让模型基于资料生成
Agentic RAG · 由 Agent 规划查询、验证证据、迭代检索并综合
Orchestration 编排 · 管理循环、工具、多个 Agent、状态与交接的控制层
Handoff 交接 · 把任务控制权从一个 Agent 转给另一个
Autonomy 自主性 · Agent 无需逐步批准即可行动的权限范围
Guardrail 护栏 · 限制输入、输出、工具和权限的规则与检查
Human-in-the-loop 人在回路 · 在审批、异常或高风险节点让人介入
Trajectory 轨迹 · 目标、观察、推理、工具调用和结果的完整运行记录
Evals 评测 · 用任务集、结局指标和轨迹评分检验可靠性
Prompt Injection 提示注入 · 外部内容伪装成指令，诱导 Agent 越权或泄密
Sandbox 沙箱 · 限制文件、网络和权限的隔离执行环境
MCP 模型上下文协议 · Anthropic 2024 年开放的工具/数据连接标准
PART 02

知识体系：看清技术栈与行业全貌

一句话总览：AI Agent = 大模型（大脑）+ 编排框架（神经中枢）+ 工具协议（手）+ 记忆数据（海马体）+ 评测观测（体检系统）+ 应用（职业）。2023 年斯坦福小镇点燃想象，2024 年 MCP 统一「接口」，2025 年 Manus / Operator / Deep Research 引爆产品化，行业正从「能跑 Demo」走向「工程化落地」。

2.3 协议三件套：MCP · A2A · AG-UI

行业已形成清晰分工：「MCP 管工具，A2A 管协作，AG-UI 管用户界面」。

MCP · 工具连接

Anthropic 2024.11 开源，被称为「AI 世界的 USB-C 接口」。统一暴露 Resources（可读数据）、Tools（可执行操作）、Prompts（模板）三类能力；2025 年初已有 1000+ 开源连接器，OpenAI / Google / 微软相继接入，后捐入 Linux 基金会。

A2A · 跨 Agent 协作

Google 2025.4 发布。解决跨厂商 Agent 如何互相发现、分派任务——每个 Agent 发布一张 JSON「名片」（Agent Card）声明能力，任务有 submitted / working / completed 等状态；2025.6 捐入 Linux 基金会，初始 50+ 伙伴。

AG-UI · 前端接入

CopilotKit 发起的开放协议。Agent 是长时运行、流式输出、非确定性的，传统 REST 不够用；AG-UI 用事件流标准化聊天流、状态同步、生成式 UI 与人在回路审批。

2.4 模型层的 Agentic 能力演进

  • 工具调用训练：从 Toolformer（Meta 2023）到各家原生 function calling，「会调工具」已成基座模型标配而非外挂。
  • Computer Use / Browser Use：OSWorld 基准上 Claude 从 2024 年底不足 15% 提升至 2026 年初约 72%，逼近人类（72.4%）；OpenAI Operator 的 CUA 模型在 WebVoyager 达 87%。
  • 长任务执行（long-horizon）：METR 研究（2025）提出「50% 任务完成时间跨度」指标——前沿模型能可靠完成的任务时长约 每 7 个月翻一倍，2025 年初约 1 小时。这是 Agent 商业化最关键的底层曲线。
  • 推理模型：o1（2024.9）、DeepSeek-R1（2025.1，开源 + RL）证明「思考更久」显著提升多步推理，直接抬高 Agent 规划能力上限；R1 开源让低成本自建 Agent 成为可能。

Agent 评测更难的五个原因：① 脚手架敏感性——同一模型换框架分数可差 10–15 分，「测的是系统，不只是模型」；② 误差复利——多步任务每步错误率相乘；③ 非确定性——同一任务跑多次结果不同，需 5 次以上取中位数；④ 无成本核算——花 $50 API 费修 $5 的 bug 也算「通过」；⑤ 污染与作弊——公开基准易被针对性优化，真实任务表现通常低 20–40 个百分点。

2.7 游戏 / UGC 场景中的 Agent（策划重点）

源头：斯坦福 Generative Agents 小镇实验（必读）

2023 年 4 月，斯坦福 Joon Sung Park 团队发表《Generative Agents》（UIST 2023 最佳论文）：25 个 LLM 驱动的 Agent 住在 Smallville 小镇，没有写死任何脚本，却涌现出社会行为——一个 Agent 被指示办情人节派对后，邀请自发传播、有 Agent 约心仪对象赴会、众人协调时间共同到场。其三段式认知架构至今仍是 LLM NPC 的标准模板：

  • 记忆流（Memory Stream）：一切经历以自然语言入库；
  • 检索评分：按 新近度 × 重要性 × 相关性 加权召回记忆；
  • 反思与规划：定期把原始观察「升华」为高层认知，再据此生成日程计划。
对策划的启示：可信 NPC 的难点不在模型而在记忆架构；行为树负责「快反射」，LLM 负责「慢思考」。2024 年该团队用 1052 名真人访谈数据构建 Agent 人口，问卷复现准确率达 85%，并于 2025 年创立 Simile 做「模拟用户群」（2026 年获 Index 领投 1 亿美元）——对 UGC 平台的「虚拟玩家测试」极具参考价值。

AI 队友 / 敌人：从 NPC 到 CPC（可协同角色）

NVIDIA ACE × KRAFTON《PUBG》Ally

业内标杆（2025–2026）：本地 ASR → 2B 小语言模型（决策核心）→ TTS；语音回复交给 TTS，游戏动作交给行为树执行（快反应不等待语言推理）。KRAFTON 称之为 CPC（Co-Playable Character）：能合作、能适应、能跨局记忆。

Inworld AI × 微软 Xbox

2023.11 合作：为开发者提供「角色引擎」（动态 NPC 反应、即时对话）+ Copilot 助理（帮策划生成任务脚本树与对话草稿）。Inworld 调研：52% 玩家抱怨 NPC「只会重复对话」——这是 AI NPC 的需求原点。

国内实践

网易《逆水寒》手游 2023 年起接入大模型驱动智能 NPC，支持自由对话与关系演化，是 MMO 中最早的规模化落地之一。

架构直觉：LLM 当「大脑」（理解意图、生成对话、高层决策），行为树 / 状态机当「小脑」（走位、开枪等毫秒级反应），两者通过工具调用衔接——这正是 Agent 技术栈在游戏内的镜像。

UGC 创作辅助 Agent

  • Roblox Build（2026.7 宣布）：移动端自然语言生成可编辑游戏 / 3D 场景，混合开源模型 + 自研模型（含 Cube：单提示生成完整 3D 场景）；移动创作 → PC 精修。同时规划测试 Agent、玩家行为分析 Agent、实验优化 Agent——直接把 Agent 用进运营环节。AI 生成内容与人工内容同标准审核、同机制推荐。
  • 生态工具：UGCraft 等第三方工具实现「2 分钟文本/图片 → 可上架 Roblox 配饰」，创作者门槛趋近于零；Newzoo 估算 2025 年全球 UGC 游戏用户超 6 亿，Roblox 占约 40%。
对 UGC 策划的三个判断：① 创作者分层将被重排——AI 抹平「会不会建模/写代码」的门槛后，稀缺能力变为创意与玩法设计本身，平台激励体系需相应调整；② 供给爆炸 → 审核与分发成为新瓶颈；③ 「AI 生成质量 ≠ 留存质量」——Roblox 坚持用同一套留存指标决定推荐，这一原则值得所有 UGC 平台借鉴。

Agent 做游戏运营与内容审核

  • 内容审核 Agent：多模态模型 + 工具调用做 UGC 初审（图文/3D/音频），人工只处理灰度案例；关键是给 Agent 配「政策知识库」（RAG）和升级机制（guardrails）。
  • 社区运营 Agent：自动巡检社区舆情、生成运营周报、策划活动草案。
  • 测试与平衡 Agent：Roblox 的游戏测试代理、Altera《Project Sid》（2024，千级 Agent 社会模拟）展示了用 Agent 群做玩法压力测试与经济系统模拟的可能——「先让 1000 个 Agent 玩一遍再上线」正从论文走向工程。
  • 虚拟玩家 / 陪玩：CPC 类技术可缓解匹配冷门时段体验问题，但需警惕「玩家知情权」与生态信任问题。

3.5 岗位与能力地图 · 转型策略

Agent PM vs 传统 PM

传统 PM 输出确定性的功能流程；Agent PM 设计的是 目标—工具—边界—评估 体系：定义任务边界（什么事不该让 Agent 做）、设计工具/API 接口（Agent 的「交互界面」是 ACI）、建立评估集与 Badcase 迭代机制、管理成本/延迟/可靠性的三角权衡。

JD 高频词：Prompt 工程、Function Calling、RAG、Workflow 编排、Agent 评估体系、MCP、多模态。加分项：能独立用 AI 工具做出 demo。

经验包装的三条翻译线

推荐系统 → Agent 分发与调度

召回/排序/重排 ≈ Agent 的工具选择、任务路由、多 Agent 编排；CTR/留存优化 ≈ Agent 任务成功率与评估迭代。「我做过的是大规模系统里『把对的内容给对的人』，Agent 时代是『把对的工具/子任务给对的 Agent』。」

UGC 生态 → AI 创作者生态

创作者分层激励、内容冷启动、供需匹配经验，直接平移到「AI 辅助创作」生态。蛋仔数据可作背书：AI 创作功能上线后超八成创作者表示「更有成就感」、超七成会分享生成内容（网易互娱×火山引擎公开案例，2025-10）。

游戏策划 sense → AI 玩法设计

讲清你如何把 AI 能力（生成、NPC、动态难度）转化为留存和 UGC 供给的游戏机制。蛋仔已接入豆包 Seedream + 影眸 Rodin 实现端内 AI 3D 生成——你就在 AI 化浪潮的第一现场。

面试立人设话术：「Agent PM 的价值不是让 AI 什么都能做，而是精确定义它该做什么、怎么评估做得好不好——这和推荐系统的策略设计是同构的。」作品 demo 现场演示 > 任何描述。

路径选择

  • 优先内部转岗：网易互娱 DreamMaker 团队、蛋仔 AI 玩法 / PC 编辑器方向与业务天然相邻；内部转岗可保留职级与股票，且你掌握的 UGC 生态数据是别人没有的资源。
  • 同步以外部 offer 校准身价：Agent 平台公司（字节扣子、阿里、MiniMax）及 AI 游戏创业公司均在招人。
  • 决策线：若内部 6 个月无窗口，带作品集外部跳槽。
